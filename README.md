# 🎬 视频播放器

基于 Python + mpv + PyQt6 开发的现代化视频播放器，拥有 B站风格的深色界面。

## 🚀 快速开始

### 方式一：直接安装（推荐）

从 [Releases](../../releases) 下载最新的 `视频播放器_安装包_vX.X.X.exe`，双击安装即可。安装包包含所有依赖，无需 Python 环境。

### 方式二：从源码运行

1. **安装依赖**：
   ```bash
   python setup.py
   ```

2. **下载 libmpv-2.dll**：
   - 从 https://sourceforge.net/projects/mpv-player-windows/files/libmpv/ 下载
   - 将 `libmpv-2.dll` 放到项目根目录

3. **运行程序**：
   ```bash
   python main.py
   ```

### 方式三：自行打包

```bash
# 需要先安装 Inno Setup（6 或以上版本均可，https://jrsoftware.org/isdl.php）
python build.py
# 输出：dist\视频播放器_安装包_vX.X.X.exe
```

> 修改版本号只需编辑 `version.py` 中的 `__version__`，打包时会自动同步。

## ✨ 功能特点

### 播放功能
- **多格式支持**：mp4, mkv, avi, mov, wmv, flv, webm, m4v, mpeg, mpg, 3gp 等
- **字幕支持**：内嵌字幕、外挂字幕（srt/ass/ssa/sub/vtt）、字幕延迟调整
- **倍速播放**：0.25x - 3.0x 倍速，满足不同观看需求
- **自定义快进**：1-300 秒可调快进步长
- **跳过片头片尾**：自动跳过片头/片尾（按文件夹保存设置）
- **音轨切换**：支持多音轨视频的音轨选择
- **进度记忆**：自动保存和恢复播放进度
- **局域网投屏**：搜索 DLNA 或旧版 AirPlay 视频接收器，投放当前视频，按设备能力提供播放/暂停、进度、音量和停止投屏

### 文件夹管理
- **播放列表**：打开文件夹自动生成播放列表
- **连续播放**：自动播放下一集
- **进度显示**：列表中显示每个视频的观看进度
- **拖放支持**：支持拖放文件或文件夹到窗口

### 界面设计
- **B站风格**：现代化深色界面，半透明悬浮控制栏，按钮全部使用图标（无文字）
- **响应式布局**：窗口变窄时自动隐藏次要按钮（先隐藏音轨/字幕，再隐藏快进/快退）
- **音量弹出面板**：点击音量图标才展开滑块，不常驻占用控制栏空间
- **自动隐藏**：控制栏在鼠标移开后自动隐藏
- **深色标题栏**：Windows 10/11 原生深色标题栏
- **自定义字体**：内置 OPPO Sans 字体，界面文字更清晰
- **Toast 提示**：操作反馈提示

### 系统集成
- **文件关联**：可设为默认视频播放器
- **文件图标**：关联的视频文件显示播放器图标
- **图标修复**：内置修复文件关联图标功能

## ⚠️ 常见问题

### mpv 找不到 / DLL 加载失败
确保 `libmpv-2.dll` 放在项目目录下，或者 mpv 已添加到系统 PATH。

### 视频无法播放
1. 确认文件格式是否支持
2. 检查 mpv 是否正确安装
3. 尝试更新 mpv 到最新版本

### 任务栏图标不显示
重启应用后图标会正确显示。

### 视频文件图标不显示
1. 打开设置，点击「修复文件图标」按钮
2. 注销并重新登录 Windows，或重启电脑
3. 注意：只有打包后的 exe 才能正确显示文件图标

### 默认播放器被其他软件替换
点击欢迎页或播放控制栏的设置按钮，选择「设为默认播放器」。程序使用随安装包附带的 PS-SFTA 组件，一键写入全部 11 种支持格式的用户默认关联，并逐项检查 Windows 实际有效关联，不需要再到系统设置中手动选择。

已在 Windows 11 build 26200 上验证上述视频格式可生效。未来 Windows 更新或组织的安全策略可能阻止该方法，此时程序会报告未生效的格式，不会误报成功。程序仅在用户点击后设置，不禁用系统保护、不申请管理员权限、不运行时下载脚本，也不阻止其他软件或用户之后更改默认关联。

PS-SFTA 1.2.0 使用 MIT 授权，固定源码版本和授权信息见 [third_party/PS-SFTA-LICENSE.txt](third_party/PS-SFTA-LICENSE.txt)。修复图标不会主动更改默认关联。即使勾选过「不再提示」，设置中的手动入口仍然可用。

### 局域网投屏
打开本地视频，点击播放控制栏的电视图标，搜索并选择设备、选择投屏画质后点击「投屏」。列表注明 DLNA 或 AirPlay。DLNA 默认使用 720p 兼容模式，也可选 1080p、2K（1440p）、4K（2160p）或原画直传。2K 上限为 2560×1440，4K 为 3840×2160，保持原比例、不放大较小视频；分别需要接收端支持 H.264 Level 5.0、5.1，并有足够网络带宽。4K 目标视频码率 16 Mbps，仍为 30fps，实际电视兼容性需现场验证。连接成功后电脑暂停本地播放；如果设备支持跳转，会从当前进度继续。投屏窗口提供暂停/播放、进度、音量、静音和停止操作。不支持的设备控制会禁用。

Vidda「HI 投屏」需先在电视打开接收页面，电脑通过 mDNS 发现旧版 AirPlay 视频接口。设备选择默认原画直传，不会自动开始整片转码；手动选兼容画质后默认使用实时 HLS，也可选完整 MP4 缓存。AirPlay 实时模式支持 720p、1080p、2K、4K、可用 GPU 编码器和转码倍速。当前未接入电视音量或配对流程，保留暂停、恢复、跳转和停止。使用 `pyatv` 的底层旧版协议，不使用其高层持续轮询播放接口。

AirPlay 不使用 DLNA 状态订阅，起播确认和手动操作后读取一次状态，正常播放只更新本地估算进度与发送速率，可点击同步图标校准。部分 HI 投屏版本片尾会返回占位时长或状态，不能保证自动识别播放结束。2026-10-05 已在 `192.168.9.33:7002` 的「客厅电视」完成一次 8 秒 H.264/AAC MP4 试播，确认有画面和声音；这不代表所有原视频格式都已验证。搜索失败时可点击加号输入 `airplay://192.168.9.33:7002`，端口变化时以设备当前 mDNS 公布的端口为准。

同日经授权用 40 秒测试片验证 HI 投屏的 `/rate`：请求 1、2、0.5 倍后，各观察约 4 秒，媒体进度均按约 1 倍前进，设备报告 `rate=1.0`。因此该设备当前接口不能通过这组原生请求实现原画倍速，不因 HTTP 请求成功而开放控制。需要倍速时选择兼容画质，通过实时 HLS 或完整 MP4 转码实现；测试结果仅适用于本次接收软件和控制接口，不代表所有 AirPlay 接收器均不支持倍速。

后续已在同一 HI 接收器验证实时 2K HLS：电视在编码器仍运行时持续读取分片，正式起播路径的 2 倍速原视频进度随约 3 秒实际时间前进约 6 秒；用户确认有画面和声音。测试音刻意调低，正式转码不降低原视频音量。播放中重建的 STOPPED 竞态已修复，并通过本机真实 FFmpeg 的改倍速、暂停恢复验证；此修复后尚未再次进行电视端切换试播。

关闭投屏窗口不会断开连接，点击电视图标可重新打开。停止投屏后，同一视频会同步回设备最后报告的进度；退出播放器会停止投屏并关闭视频服务。

电脑和设备需处于同一 IPv4 局域网，接收端需支持 DLNA MediaRenderer 或无需配对的旧版 AirPlay 视频。设备需开启投屏接收，Windows 防火墙需允许播放器在专用网络中接收连接。没有发现设备时检查访客网络隔离、VPN、防火墙和接收端设置；程序不会自动关闭防火墙或创建管理员规则。

原画模式以原文件传输，不先转码或完整缓存；传输方式、编码器和倍速禁用并显示「此模式不可修改」，切回兼容画质后恢复正常选项。接收设备必须支持原文件的容器、视频和音频编码。兼容模式使用 FFmpeg 转为 H.264 Baseline 8-bit、30fps、AAC 双声道，按所选 720p/1080p/1440p/2160p 限制画面尺寸并保留宽高比，不放大小视频。安装源码依赖时会通过 `imageio-ffmpeg` 获取转码工具，也可使用 PATH 中已有的 FFmpeg。

兼容模式默认选择「实时（边转边播）」：DLNA 在设备请求后启动 FFmpeg，以 MPEG-TS 经 HTTP 流式输出；AirPlay 先准备约两个 2 秒 HLS 分片，再把播放列表交给电视，编码仍继续进行，不等待整部转码。HLS 播放列表保留最近 6 个分片，额外保留少量旧分片，停止或退出后终止编码进程并删除临时目录；不会作为整片缓存长期保留。HLS 播放列表刷新属于视频读取，不是设备状态轮询。

实时模式不声称支持整个视频的字节范围跳转，拖动进度或改变倍速会停止旧流，从原视频目标时间重建并连接，可能短暂缓冲。AirPlay 暂停后恢复也会从暂停进度重建 HLS，避免继续读取已经被滚动清理的分片。首次还需电视起播缓冲；实际效果取决于电脑编码速度、网络及设备的 MPEG-TS/HLS 支持，不能保证所有接收器均能播放，不支持时可手动选择完整缓存。

编码器默认选择「自动（GPU 优先）」，按 NVIDIA NVENC、AMD AMF、Intel QSV 的顺序选择通过本机试编码检测的 GPU；没有可用 GPU 时使用 CPU。也可手动选择可用的硬件编码器或 CPU，实时和完整缓存模式都支持。检测在后台进行，同次运行复用结果；原画直传不需要编码器。此功能仅加速 H.264 视频编码，解码、缩放和音频编码仍由 CPU 完成，不保证消除网络或接收端造成的卡顿。运行中编码失败会报告错误，不自动重发投屏；可手动切换 CPU 再试。

兼容模式可选择 0.5–3 倍速，默认 1 倍，音频保持音调。实时模式可在播放中切换，从原视频当前进度重建视频流，可能短暂缓冲；暂停时切换仍保持暂停。完整缓存模式只能在投屏前选择倍速，改变倍速需停止后重新准备；不同倍速使用独立缓存。原画直传不支持倍速。进度显示、跳转和停止后恢复本地播放均使用原视频时间轴。较高倍速需要更高解码和转码速度，实际流畅性仍取决于电脑、网络和接收端。

设备不支持实时流时可手动选择「完整缓存（备用）」，先转为带完整长度和 HTTP Range 支持的 MP4 再投屏。此模式可能耗时较久，窗口显示已编码的视频时间；准备期间点击停止按钮可以取消，退出程序也会终止转码并清理临时文件。原文件不会修改，完整结果缓存于 `%LOCALAPPDATA%\VideoPlayer\cast-cache`，相同原文件和画质再次投屏会复用缓存。缓存需要额外磁盘空间，不需要时可在停止投屏后删除该目录。不会自动切换模式、重试投屏或开始整片转码。

播放器本地设置的外部字幕、音轨选择、倍速、片头片尾跳过不会同步到电视；兼容模式使用原文件的第一条音轨。本功能不是桌面镜像，不支持需要配对的 AirPlay 2 或 Google Cast。只开放当前视频的随机 URL，不公开文件目录；停止投屏或退出程序后关闭该服务。

开发验证：`python -m unittest discover -s tests -p test_casting.py -v`。测试覆盖文件访问限制、断点读取、后台控制和真实 UPnP 库与模拟接收端的通信；真实设备播放仍需现场验证。

### 投屏调试
本地 mpv 能播放，不代表接收设备能解码。设备提示「未知格式」时，检查视频和音频编码，而不仅是文件扩展名；HEVC Main 10、高分辨率或高帧率视频可能超出设备能力，可选择 720p 兼容模式作对照。兼容视频输出格式已经过本机解码和 HTTP 断点读取验证，但设备播放成功仍需实机确认，不能仅凭转换成功判定根因已解决。

程序只在确认设备进入播放状态后才暂停本地播放，实时模式还需已经向设备发送首批视频数据。实时模式等待起播最多 30 秒，原画或完整缓存模式为 15 秒；未起播、编码失败、显式状态查询失败或播放停止会释放会话，可再次手动投屏，不会自动重发视频地址或播放命令。

播放状态改为 DLNA `SUBSCRIBE/NOTIFY` 通知，订阅由库自动续期；正常起播后不再每 2 秒或按固定周期查询。起播确认期间仍会有限次读取状态，播放/暂停、跳转、倍速、音量操作后也会校准一次。停止或退出时取消订阅并关闭通知服务。设备或防火墙不支持推送、订阅失效时显示「手动同步」，不会自动恢复轮询；点击遥控栏的同步图标可读取设备实际状态和进度。

DLNA 不保证持续推送精确进度，因此进度条由本地时钟平滑估算，并依据暂停、恢复、跳转和手动同步校准；缓冲或设备侧跳转可能使估算有偏差，进度条提示会注明。推送模式仍依赖接收端发送状态事件及防火墙允许通知进入，不能保证不支持事件的设备也能即时更新。

连接信息右侧显示实时「推送 Mbps」，按最近 1 秒实际写入 HTTP 连接的视频有效载荷计算，约每 250 毫秒本地刷新；实时转码、原画和完整缓存模式均支持，HEAD 请求不计入。没有发送数据时归零，跳转或停止后重置。此数值不是编码器目标码率、网络带宽上限或接收端已播放的速率，不包含 HTTP/TCP 开销与重传；设备预缓冲时可能较高，缓冲完成后也可能暂时为零。刷新只读取本机计数，不向设备查询状态。

在投屏窗口勾选「调试日志」，重新点击「投屏」。窗口会显示正在执行的步骤，超时错误会指出失败阶段。点击文件图标打开运行日志，点击复制图标复制完整错误。

设备在线但广播搜索不到时，点击加号，输入设备的 HTTP 描述地址来直接添加（通常可在设备的 SSDP 响应中获取）。添加后，本次运行中的刷新会同时读取已知设备地址；此功能不保证视频播放成功，仅绕过广播发现。地址仅接受局域网 IPv4，不支持公网地址或媒体服务器。

默认仅保留警告和错误，不记录正常播放请求和步骤。开启调试日志后会记录设备地址、视频地址、SOAP 请求和响应、每个投屏步骤的耗时、完整异常堆栈，以及接收设备对视频的 GET/HEAD 和 Range 请求。若投屏失败前完全没有视频请求，只能说明设备未能访问或尚未尝试访问视频服务，需结合失败动作检查网络、防火墙或设备行为，不能仅凭超时判定编码问题。日志可能含本地文件名和局域网信息，分享前注意隐私。

也可从 PowerShell 启动源码调试：`python main.py --debug`。安装版在程序目录执行：`& '.\视频播放器.exe' --debug`。传入视频文件时支持 `--debug` 与文件路径同时使用。日志优先保存在播放器程序目录的 `crash.log`，无写入权限时退回 `%APPDATA%\VideoPlayer\crash.log`。

### 根目录出现 crash.log / fault.log
这是正常现象：普通启动不再追加正常启动或播放记录，仅在警告、错误或手动开启调试时写入 `crash.log`；`faulthandler` 仍监听底层崩溃并写入 `fault.log`，没有崩溃时该文件通常为空。运行日志按 1 MiB 轮转并保留最多两份备份，底层崩溃日志在启动时达到 1 MiB 则保留一份旧记录。日志已被 `.gitignore` 忽略，可在退出播放器后删除，重新运行会自动重建，不影响功能。

## 📦 打包为安装包

```bash
# 需要先安装 Inno Setup（6 或以上版本均可，https://jrsoftware.org/isdl.php）
python build.py
# 输出：dist\视频播放器_安装包_vX.X.X.exe
```

打包完成后 `dist\` 目录只保留安装包，中间产物自动清理。若只需要 PyInstaller 的一目录输出（不生成安装包），可使用 `python build.py --dir-only`。

**修改版本号**：只需编辑 `version.py` 中的 `__version__`，打包时自动同步到安装包文件名和安装界面。
